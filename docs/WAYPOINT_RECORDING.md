          AL*          BL*          BQ*

                                           C2+     C6+     C10+

          AF*          BF*                 C4*     C8+     C12*
          H*                                             CQ*
     0  ------------------------------------------------------------> +X
          0       1000      2000      2800      3600      5200 mm

  BL* = B_LAST*(x_BL, y_BL, v)    BQ* = B_QR*(x_BQ, y_BQ, qB)
  CQ* = C_QR*(x_CQ, y_CQ, qQ)    C1*/C4*/C9*/C12* 使用共同 yaw qC

建议的静态/动态路线关系：

  HOME
    -> A_FIRST, A2, A3, A_LAST
    -> B_QR

注意：上图中的星号位置是“机器人 base_link 应停车的位置”，不是果蔬、果树或

## 1. 这份路线保存什么

`fruit_waypoint_recorder` 后续应改成一次性完成整场路线模板标定，而不是把车开到现场后按手柄逐点记录。

路线模板包含以下 11 个手动锚点：

| 点击序号 | 锚点 | 用途 |
| ---: | --- | --- |
| 1 | `HOME` | 起始区中的出发/返航停车姿态 |
| 2 | `A_FIRST` | A 区作业方向上的第一个停车点 |
| 3 | `A_LAST` | A 区作业方向上的第四个停车点 |
| 4 | `B_QR` | B 区二维码识别停车姿态 |
| 5 | `B_FIRST` | B 区作业方向上的第一个停车点 |
| 6 | `B_LAST` | B 区作业方向上的第四个停车点 |
| 7 | `C_QR` | C 区二维码识别停车姿态 |
| 8 | `C1` | C 区左列最上方候选停车点 |
| 9 | `C4` | C 区左列最下方候选停车点 |
| 10 | `C9` | C 区右列最上方候选停车点 |
| 11 | `C12` | C 区右列最下方候选停车点 |

这里的 `FIRST` 和 `LAST` 表示机器人实际执行该区域时的先后顺序，不强制表示图纸上的上方或下方。若最终决定反向通过 B 区，就按实际行驶方向点击 `B_FIRST` 和 `B_LAST`，不要再在程序中把点倒序。

规则图上的毫米尺寸只能帮助确认区域和编号。真正保存、显示和执行的坐标必须来自 RViz 中的 `map` 坐标，不能把规则图的毫米数直接当作当前 PGM 的坐标。

## 2. yaw 标注约定

在 RViz 中打点时，按住鼠标拖出朝向箭头。文档和调试日志统一用下面四个 ASCII 符号表示 yaw：

| 符号 | 朝向 | yaw |
| --- | --- | ---: |
| `>` | `+X` | `0` |
| `^` | `+Y` | `+pi/2` |
| `<` | `-X` | `pi` 或 `-pi` |
| `v` | `-Y` | `-pi/2` |

执行时仍保存完整四元数；箭头符号只用于人看和检查。

- `HOME`：箭头指向机器人比赛启动时的车头方向。
- `A_FIRST`、`A_LAST`：箭头沿 A 区通道的执行方向，两者应基本一致；A 区生成点复制该组 yaw。
- `B_FIRST`、`B_LAST`：箭头沿 B 区通道的执行方向，两者应基本一致；B 区生成点复制该组 yaw。
- `B_QR`、`C_QR`：箭头应让用于扫码的相机正对二维码牌，不按通道方向猜测。
- `C1`、`C4`、`C9`、`C12`：当前 KISS 版本要求四个箭头使用同一个作业 yaw，生成的 `C1` 至 `C12` 全部复制这个 yaw。若以后不同列必须使用不同朝向，应升级模板格式，不要在当前版本里加入隐式特例。

## 3. A、B 区自动生成

A、B 区各有 4 个机器人停车点，只手动点击执行方向上的首尾两个点，中间两个点按直线等距生成。

以 A 区为例，令首尾位置分别为 `P0` 和 `P3`：

```text
A1 = P0
A2 = P0 + (P3 - P0) / 3
A3 = P0 + 2 * (P3 - P0) / 3
A4 = P3
```

B 区使用相同公式生成 `B1` 至 `B4`。生成前必须检查：

- 首尾点距离足以形成 4 个不同停车点。
- 首尾 yaw 的最短角差在允许范围内。
- 生成后的 4 个点都位于同一条可行驶通道，不落在果蔬、果树或围栏上。

这些检查只验证几何关系，不通过测试锁死现场坐标、间距或 yaw 数值。

## 4. C 区四角生成 12 个候选点

C 区候选位置按规则编号为 3 列、每列 4 行：

```text
左列       中列       右列
C1         C5         C9
C2         C6         C10
C3         C7         C11
C4         C8         C12
```

只手动点击四角 `C1`、`C4`、`C9`、`C12`。程序使用双线性插值生成中间 8 个点，这样可以保留 PGM 上轻微的旋转或梯形误差，而不是假设地图一定横平竖直。

对列号 `c = 0, 1, 2`、行号 `r = 0, 1, 2, 3`，定义：

```text
u = c / 2
v = r / 3

P(c, r) = (1-u)(1-v) * C1
        + (1-u)v     * C4
        + u(1-v)     * C9
        + uv         * C12

position_id = 1 + 4*c + r
```

例如：

- `C5` 是 `C1` 与 `C9` 的中点。
- `C8` 是 `C4` 与 `C12` 的中点。
- `C6`、`C7` 位于中列，并分别处在从上到下的第 2、3 行。

规则图给出的候选中心大约为 `x = 2000/2700/3400 mm`、`y = 2000/1500/1000/500 mm`，只能用于检查编号方向。实际四角仍必须点击机器人停车姿态，而不是照抄这些中心数值。

## 5. C 区比赛时动态生成 9 点

C 区实际执行点不能在赛前固定，因为二维码决定 8 个 `position_id` 及其严格顺序。

加载路线模板时先生成并保存 `C1` 至 `C12` 的查找表。收到 `/fruit/c_pick_plan` 后：

1. 验证计划包含恰好 8 个任务。
2. 验证每个 `position_id` 位于 `1..12`，且没有重复位置。
3. 保持二维码任务原顺序，禁止按距离重新排序。
4. 生成 C 区实际路线：`[C_QR, C[id_1], ..., C[id_8]]`。
5. 每个动态点同时保留二维码中的 `sequence`、`position_id` 和 `target`，供总控、播报和采摘逻辑使用。

若二维码计划还未确认，导航只能显示 C 区 12 个候选点，不能擅自选择 8 个点开始比赛。

## 6. 一条龙打点流程

1. 启动地图、GICP 重定位、RViz 和路线编辑模式。
2. RViz 使用标准 `SetGoal` 工具；每次点击后，编辑器按表格顺序自动切换到下一个锚点名称。
3. 每个点都先点击停车位置，再拖出车头朝向；二维码点的朝向优先保证扫码。
4. 点击完 11 个锚点后，编辑器生成 A/B 中间点和 C 区全部 12 个候选点。
5. 在 RViz 中逐个检查点号、坐标、yaw 和停车空间；发现错误时用“撤销上一个锚点”返回修正，不能只改生成结果。
6. 保存路线模板。保存内容包括手动锚点、生成参数和生成结果，便于加载时复核。
7. 重新加载一次模板，确认显示结果与保存前一致，再把该文件用于比赛启动。

## 7. 加载后在 PGM 上显示

PGM 原图保持不变；所有点通过 RViz Marker 叠加显示，避免把调试标记永久写进地图图片。

加载模板后应显示：

- 手动锚点：星形或较大的实心标记，并显示 `HOME`、`A_FIRST` 等名称。
- A/B 生成点：按执行顺序显示 `A1..A4`、`B1..B4`。
- C 候选点：全部显示 `C1..C12`，并使用与 A/B 不同的颜色。
- yaw：每个点显示一根短箭头。
- 当前最终路线：用醒目的序号和连线显示真实执行顺序。
- C 二维码确认后：选中的 8 个 C 点高亮并标注二维码序号，未选中的 4 个候选点变暗但不删除。

显示中的“连线”只表示任务顺序，不代表 Nav2 路径，也不生成 costmap。当前版本不考虑动态避障；控制器直接按点序执行，现场必须保证预设路线可通行。

## 8. 保存前检查清单

- [ ] `HOME` 位于起始区内，返航后整车投影满足规则。
- [ ] A/B 首尾锚点确实对应各自执行方向，不会生成反向序列。
- [ ] A/B 的 4 个生成点都能稳定停车并覆盖该区域需要处理的位置。
- [ ] `B_QR`、`C_QR` 的相机朝向能稳定读码。
- [ ] C 四角编号没有点反：左列 `1 -> 4`，右列 `9 -> 12`，均为从上到下。
- [ ] C 四角使用一致的作业 yaw。
- [ ] C 区 12 个生成点均在可停车位置，且 `position_id` 与规则图一致。
- [ ] 加载后所有点都能在 PGM 上看到名称、顺序和 yaw。
- [ ] 模拟一份 C 二维码计划后，最终 C 段恰好为 `C_QR + 8` 个点，并保持二维码顺序。
- [ ] 当前版本未启用动态避障、costmap 或障碍物自动绕行。
