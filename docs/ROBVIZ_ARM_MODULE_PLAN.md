### 2.1 二维快速姿态编辑器

用户新增要求：二维三连杆、左右滑块、末端角度滑块，用于快速生成姿态和插入航点。
二维视图采用当前偏航方向的径向距离与高度平面，不是固定世界 XY 平面。
显示大臂 a2、小臂 a3、工具 a4 三段，基座高度 d1 和真实 TCP 偏移另行标注。
腕轴、a4 末端和真实 TCP 是不同点，不能把偏移画成不旋转的世界 Z 平移。
底座滑块控制 yaw，末端滑块控制 a4 的绝对 pitch，不是原始腕电机角。
两个滑块只更新预览，不随拖动下发真实运动。
二维主要拖动对象为真实 TCP，保留当前 pitch，调用现有高位构型 IK 调整三连杆。
径向距离限制为非负，底座方向由 yaw 滑块控制，不跨过原点悄悄翻转偏航。
既有关节角表单仍可使用，不增加第二套手动关节拖动模式。
拖动失败时显示候选目标和原因，保留最后有效姿态，不把失败解当成零角度。
原点附近沿用当前 IK 的 yaw=0 约定，显示实际求解结果，不声称任意 yaw 仍被保留。

每次有效调整显示 TCP XYZ、pitch、连杆角和原始硬件角。
角度转换、IK/FK 与限位校验仍调用机器端共享数学模块，浏览器只进行绘图坐标投影。
预览请求允许最新值覆盖，迟到结果不能覆盖更晚的拖动或其他机器的状态。
“插入航点”只更改草稿，“执行当前姿态”才调用正式服务。
用户已确认直接执行当前编辑姿态，整套工序仍先保存并重载。
播放时间轴不自动把任意中间帧改为实机目标，执行按钮使用明确标出的编辑目标。

生成姿态后提供“选中点后插入”“追加到末尾”“替换选中点”三个显式操作。
target 按当前预设类型填充，Cartesian 用 TCP，joints 用硬件角，link_angles 用现有连杆角。
新点时长默认取当前 planner 配置，夹爪默认 HOLD，其余可选项保持省略语义。
替换默认只替换姿态 target，保留该点的时长、夹爪和路径属性。
替换完整航点需要另行明确编辑，不由一次拖动隐式覆盖。

### 2.2 启用和 jog

每次进入页面默认只读预览，需要显式启用实机控制。
启用时要求操作者确认其他运动客户端已停止、硬件就绪且现场安全。
启用后执行按钮直接提交，不对每次动作增加弹窗。
刷新、离开页面、切机器、断连和失焦清除启用状态，恢复后需重新启用。
STOP 和 ESTOP 不依赖启用开关，但仍要求服务可连接。

jog 初始 XYZ 步长为 0.01 m，pitch 步长为 5°，PTP、HOLD、duration_ms=0。
网页可调步长，但不改 planner 的 default_duration_ms 或标定。
只在 jog 已启用且控制区获得焦点时绑定键盘，不拦截输入框或编辑器按键。
原地夹爪动作以新鲜实测角提交，待夹爪动作优先于未提交的累计 Cartesian 目标。
任一服务失败、反馈无效或停止事件清空未提交目标，不自动重试。
夹爪按钮改变的动作与航点记录属性分别显示，不假装 HOLD 能撤销已提交的 CLOSE。
失焦时只停止本页尚在运行的 jog，不因曾经启用 jog 而停止后来显式提交的预设。
停止按钮清除本页输入，提示“STOP/ESTOP 已请求”，不将服务应答当成硬件停稳。
硬件停稳需新鲜、有限速度反馈确认，反馈无效或缺失时显示“停稳未确认”。

## 3. 预设编辑契约

配置源为 `src/fruit_arm_planner/config/arm_presets.yaml`。
实际预设名称从文件读取，不复制 README 的历史名称列表。
当前工作区 `pick_sequence` 已被注释，不能把注释内容当成可执行预设。

编辑支持的字段包括：

- 预设名称、description、coordinate_frame。
- 航点 target、duration_ms、gripper、dwell_ms、linear、is_via_point。
- 新增、复制、删除、排序、撤销及实测快照追加。

`cartesian` 的 XYZ 为真实 TCP 米坐标，第四项为 a4 绝对 pitch 度。
`link_angles` 使用现有控制台连杆角约定，`joints` 为原始硬件角度。
切换 coordinate_frame 不能仅改标签并重解释旧数字。
用户确认已有航点时锁定类型，不提供自动跨类型迁移。
转换采用新建副本后手动录入或实测填充，不能静默重解释旧 target。

`linear` 只位于航点内，LIN 只能用于 Cartesian。
`is_via_point` 按当前实现保留，包括带夹爪或驻留的点，不新增废弃草案的强制停稳约束。
`dwell_ms` 未填写、显式 0 和显式正数需要保持区分。
当前 HOLD 航点不生成夹爪驻留段，不能按字段名称假设一定驻留。
PTP/LIN 生成的插值点和夹爪驻留点都计入 2..64 点容量。
预览显示实际生成点数、总时长及失败航点，不能只显示用户关键点数量。

### 保存保障

复用现有 HTTP 文件目录白名单、版本冲突、备份和原子替换模式。
浏览器不提供任意文件路径，不上传整份未经约束的配置覆盖请求。
默认只修改授权区块，保留标定、注释、未知字段和其他预设。
先核对 `validate_presets`，再进行预览规划校验。
路径可达性依赖起点，不可把某个起点的失败永远当成文件格式错误。
保存冲突返回 409，保留用户草稿，不静默覆盖外部修改。
文件保存成功不等于 planner 内存已更新，重载失败需单独展示。
用户确认保存和重载为两个独立操作，不保存后自动重载。
首版仅编辑 presets，geometry、joint_mapping、planning 只读。
不提供进程重启按钮，不改变原控制台和 mission 的配置读取来源。

### 草稿恢复

用户确认草稿按当前机器保存到 pluginStates，并随网页配置导入导出。
记录基线文件版本、编辑草稿和 UI 状态，不记录待执行动作或实机启用状态。
恢复草稿后重新读取文件并核对版本，冲突保留草稿，不自动保存、重载或执行。
设备切换时不能把一个机器的草稿保存到另一个机器。

## 4. 预览与数据通路

当前 planner 没有只规划服务、预设目录服务或文件编辑服务。
浏览器也不能直接读取机器人本机 YAML。
用户同意机器端补充文件及纯预览支持，不改下位机执行方式。
用户另同意最小只读 planner 内存配置快照接口，用于预览与运行配置一致性检查。

在 `fruit_robviz_bridge` 的现有 HTTP 服务添加机械臂文件和预览端点。
预览调用 `RobotKinematics`、`JointTransformer`、`TrajectoryPlanner`，不产生 ROS 运动发布。
预览返回完整路径、各关节位置、FK 连杆节点、TCP、时刻、夹爪事件和点数。
前端不得实现第二套 IK、耦合映射或标定常量。
FK 的 `points=[p0,p1,p2,p3,p4,tcp]` 可直接用于首版连杆示意图。
当前工作区未发现已跟踪的机器人 URDF/xacro，需要区分示意几何与实体模型。
用户选择首版 3D 连杆示意、实测与目标叠加、完整路径播放和时间轴。
首版不要求制作实体 URDF，不引入实体碰撞检查。
已有 URDF 页只跟随普通 `/joint_states`，不能直接套在自定义 ArmTelemetry 上。

实测、目标和预览姿态必须有不同的图例与数据来源标识。
预览播放和拖动时间轴不调用实机服务。
三维姿态和预览默认在 `arm_base_link`，不把它当 camera、base_link 或 odom。
规划通过不代表无碰撞，也不保证下位机连续轨迹严格等于渲染折线。

### 4.1 只读配置快照

拟新增 `/arm_planner_node/get_configuration`，类型 `fruit_interfaces/srv/GetArmPlannerConfiguration`。
请求为空，应答字段拟为 `success`、`message`、`config_path`、`revision`、`configuration_yaml`、`max_trajectory_points`。
revision 表示内存 geometry、joint_mapping、有效 planning 和 presets 的语义版本。
configuration_yaml 是内存快照的序列化，不是临时重新读取的磁盘文件。
max_trajectory_points 来自 planner 的当前容量约束，首版实际为 64。

初始化时记录实际加载配置，reload 成功时仅更新快照中的 presets 及版本。
reload 失败保留旧快照，查询和重载采用现有锁保证一致读取。
查询可以在运动期间执行，不等待当前动作结束，也不取得运动占用。
既有运动服务、消息、执行等待和下位机线协议不变。
不提供配置修改、使能、运动或进程管理副作用。

磁盘原始字节 hash 只用于保存冲突，不直接与内存语义版本比较。
HTTP 返回文件的同规则语义版本，界面才能区分纯注释变化与真正配置变化。
磁盘 geometry、mapping 或 planning 不同于内存时提示需安全重启，不用 reload 伪装生效。
新服务未部署时可读取文件并编辑，但当前内存版本标为未知，不声称配置一致。

### 4.2 拟议 HTTP 数据契约

机械臂 API 使用 `/api/arm/` 前缀，不复用导航文件 ID 或影响已有航点 API。
单一配置路径由服务器配置白名单决定，浏览器不能指定任意路径。

| 接口 | 输入 / 输出与副作用 |
| --- | --- |
| `GET /api/arm/document` | 返回配置白名单 ID、文件字节版本、文件语义版本、只读配置与 presets，读取无副作用 |
| `PUT /api/arm/presets` | 接收基线文件版本与预设编辑内容，仅修改 presets，返回新版本与备份位置，不自动 reload |
| `POST /api/arm/pose` | 接收配置快照与 Cartesian/硬件角/连杆角/模型角输入，返回有效性、各角度、FK 六节点与 TCP，不发运动 |
| `POST /api/arm/preview` | 接收配置快照、start_hw_rad 和单目标或草稿工序，返回原 planner 点流、FK 路径、时刻与失败原因，不发运动 |

在线时前端经 ctx.bridge 读取当前内存快照，再交 HTTP 数学预览使用。
离线模拟明确采用磁盘配置或已有快照，携带配置来源与版本，不冒充当前节点。
HTTP 仍须校验配置和请求形状、有限值、长度、枚举、时长、限位和请求体大小。
客户端提供的快照只参与只读计算，不能据此覆盖服务器配置或放宽实机限制。
运行状态中的 model_joint_state 直接用于 FK，不再逆映射一次。

末端拖动按最新候选合并请求，限制并发，旧结果不能覆盖新请求。
实测绘图更新采用相同的 FK 接口和有界刷新，不每个浏览器帧创建请求。
任何预览配置、起点、目标或时长改变都使原路径预览失效。
不自动裁减超过容量的点流，也不改变插值参数来让错误悄悄通过。

### 4.3 规划逻辑单一来源

复用现有三个数学模块，不在 bridge 或 TypeScript 复制公式。
单目标服务当前在回调中组装规划，实施时把需要共享的纯组装逻辑放回 planner 包。
节点和 HTTP 预览共同调用该入口，保持时长默认、采样、夹爪、驻留及首点语义一致。
仅做本模块需要的最小提取，不重构整个执行节点，不改变占用或硬件结果等待。
规划核心生成并校验点流，执行节点另校验新鲜反馈、硬件状态及单一运动占用。
纯预览可以接受手动起点，但不能绕过限位和路径校验。

## 5. 执行与会话问题

现有网页服务通路有两层固定 10 秒超时：

1. `WorkerBridge.callService` 的 Promise 超时。
2. `FoxgloveConnection.callService` 的底层请求超时。

当前 planner 等待下位机匹配终态，不设置运动执行期限。
超过 10 秒的预设会触发前端超时，但机械臂可能仍在运行。
必须解决两层等待契约，不能只改其中一层，也不能调用超时后自动重发。
推荐最小通用改动：支持每次调用指定等待策略，普通服务仍保持原默认。
机械臂插件同时订阅遥测，明确显示执行中、确认完成、失败或结果未知。
用户确认增加每次调用的等待策略，仅运动和 Home 调用不设置执行期限。
普通查询、重载与停止服务继续使用原默认等待期限。
两层服务等待以及 Worker 消息协议必须同步传递该选项。
不改变 planner 的现行服务类型和 MCU 执行终态判定。
通用调用选项拟为 timeoutMs：省略保留 10000，null 表示不设等待期限，正有限数表示毫秒。
两层不设 timer 时仍保留断连、Worker 崩溃、dispose 及连接代际的拒绝清理。
网页不发送无结果的第二次动作，不通过无限等待掩盖断连或停止失败。

正式服务没有客户端 action ID，`trajectory_id` 只在响应中返回。
网页发出请求后看到新的遥测 ID，不足以证明该轨迹一定属于网页。
mission、控制台或其他网页可能提交动作，planner 的单一占用只防止同时执行。
用户选择首版独立人工调试，手动控制前停止 mission 和其他运动客户端。
mission 运行时只观察与编辑草稿，不新增任务暂停、接管、恢复或抢占机制。
页面显式启用仅表示操作者确认调试条件，不证明系统已经停止所有其他客户端。
当前连接内为每次本页调用记录本地编号，服务 Promise 是本页结果的关联依据。
遥测只显示全局硬件状态，不能通过“刚变化的 ID”猜测本页请求成功。
连接更换或断连使未完成请求转为结果未知，旧连接结果不得更新新连接页面。
普通切页不取消已经提交的 ROS 请求，返回后展示新鲜硬件状态，不重复提交。

切页、换机器、浏览器失焦、断网和关闭标签是不同生命周期事件。
停止输入和取消本地 Promise 不等于向机器人发 STOP，更不等于硬件停稳。
不能承诺断网后浏览器一定能发送停止命令。
用户确认离开页面、切机器或失焦时停用 jog、清空未提交目标，在线时尽力请求 STOP。
显式执行的单目标和预设不因普通切页自动中断，按原 planner 逻辑继续执行。
只读观看时不会因离开页面发 STOP，不停止其他控制源的动作。
返回后先核对新鲜实测状态，jog 必须显式重新启用，任何动作都不重放。

### 5.1 草稿与执行

第二轮确认整套预设只执行已保存并重载的版本，未保存工序只做完整预览。
单目标控制与单个预览姿态可以直接执行，不必先保存成预设。
用户已确认不扩大到未保存多航点执行，不增加草稿运动服务。
“执行当前姿态”使用原 move_cartesian 或 move_joints，最终点保持原精确目标语义。
该操作不执行所选航点的 dwell_ms 或 is_via_point，界面明确提示两者仅工序执行生效。
完整工序预览可以有这些属性，但播放、保存和执行保持独立操作。
正式预设执行前再次核对文件与内存的 presets 语义版本，未重载时不能执行草稿。
本页无法建立跨文件编辑与 ROS 运动的原子事务，其他工具变更后必须重新核对。
不通过临时覆盖正式预设、匿名占用预设名或原始轨迹发布绕过这个决定。

### 5.2 预览起点

在线默认使用新鲜实测姿态，用户可以切换为手动指定的预览起点。
手动起点明确标注为模拟数据，不写入实时状态或替代实机执行起点。
ROS 断连但 HTTP 可用时，可基于手动起点预览，不需要真实硬件执行。
HTTP 不可用时保留草稿与最近预览，但不宣称已用当前配置重新规划。
实机执行时 planner 仍从当时的新鲜反馈重规划，不直接下发先前预览点流。
点击执行前核对连接、有效新鲜四轴遥测、内存版本及本页请求状态，过期预览需先更新。
这些网页检查不是机器人安全控制替代品，planner 仍执行自己的占用和反馈校验。

## 7. 验证范围
