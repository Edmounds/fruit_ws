# A/B/C 语音播报全流程

本文描述 mission 的源码时序，不是硬件验收。当前范围为 A/B/C 任务，语音播报采用维什戴尔（Wis'adel）**gremlin** 音色预生成短语素材与本地 WAV 拼接播放，比赛期间完全离线运行（不依赖 GPU 服务器、不实时合成）。

`full` 完成 C 区后沿现有 C 区路径前往 `C_top_waypoint_1`，对齐该航点保存的 yaw 后调用采摘记录汇总播报。其他入口结束位置不变。不增加 D 区、换筐或返回起点流程。

ABC 编排在 `src/fruit_mission/fruit_mission/Logic_abc.py` 审核，ACB 在同目录的 `Logic_acb.py` 审核，ACBD 在同目录的 `Logic_acbd.py` 审核。
各入口写分区顺序和 A 区路线，共用 B/C 作业、采摘、二维码和播报细节在 `actions.py`；
ROS 反馈、STOP 和实测停稳留在 `MissionContext`。见[mission 说明](../src/fruit_mission/README.md)。
单独 B/C 调试也先扫码，再调用同一个分区函数；保留 `--flow full|ac|a|b|c`。

```text
起点播报 → A 区 → B 二维码计划播报 → B 区 1～8 号树逐树
→ C 二维码计划播报 → C 区按二维码行序逐项
→ C_top_waypoint_1 到点并对齐 yaw → 任务流程结束 → 采摘记录汇总
```

## 等待与局部故障

### ACB 与 ACBD 汇总规则

ACB 与 ACBD 的播报顺序前半程一致，均为起点、B 二维码、A 回程、C 二维码及作业、A+C 汇总、B 作业。
完成 C 区后沿图前往 `C_top_waypoint_1`，对齐保存的 yaw。
成功到点才播报“本次采摘记录”和各品种数量，零记录时播报“本次没有采摘记录”。
中途不播报“任务流程结束”，不清空累计数量，等待播报后继续返 B。
到点失败时跳过中途汇总。
ACB 在 B8 作业结束后直接结束，不再次汇总。
ACBD 在 B8 作业后进入 D 区（D1～D7），D 区不扫码，直接识别并采收成熟苹果和梨。
D 区不播报点位号，仅复用现有语音素材；同树首抓前播报对应实际品种（“识别到成熟苹果/梨子，开始抓取”），同树后续抓取不再报识别；每次放筐入仓完成后播报“采摘完成”。
无果实、不成熟、导航失败或机械臂报错等异常均彻底静默，不播报跳过或失败，直接安全收臂或推进下一作业点。
D7 作业结束后直接结束，不再次汇总。
ABC 的结束播报和默认入口保持不变。

### 共用等待规则

- 同步语音等待最多 10 秒；播放器由单个 FIFO 后台线程串行执行，避免语音重叠。
- 缺失素材、未知文本或播放设备失败只告警跳过当前条目，不结束比赛；不播残缺事实句。
- 机械臂运动等待下位机结果，不设前端期限；识别、二维码和端点等待分别限时，不共用整个工序的 10 秒预算。
- 局部失败播报并跳过，继续整场流程。未知运动仍须取消/STOP、确认安全后执行一次 Home；没有非导航重试。恢复不安全时跳过危险动作，不假报成功。
- `Ctrl-C` 或异常退出时立即终止当前音频播放并清空未播队列，不播报汇总。

## 起点与 A 区

起点同步播报（失败/超时仍继续）：

> 我们是重庆大学 RoboCup 水果采摘队伍，现在开始采摘

A 区没有正常逐点语音。导航与 left_look 并行，到点且 Look 完成后开启 harvest 窗口识别。
左侧目标 CLOSE、驻留 → left_harvest 末点 OPEN、驻留 → Home；然后 right_look 及右侧对应工序。
工序确认完成后按实际识别品种计入采摘统计。
局部失败安全恢复并跳过，不因普通识别或运动失败提前退出整场比赛。

## B/C 二维码

二维码导航、QR 姿态或解码失败均使用 mission 独立配置
`src/fruit_mission/config/qr_fallback.yaml`，照常保存、播报和执行该区域。
不因二维码失败跳过整个区域。

- B 二维码摘要异步分项播报，随后 Home、导航可以与语音并行。
- C 二维码摘要扫码解码后立即异步播报，小车直接收臂出发进入转场导航，原地 0 秒等待，语音在后台边走边播。
- 播报不阻塞底盘导航与机械臂动作。

兜底 B 摘要：

> 一号梨子；二号苹果；三号梨子；四号苹果；五号苹果；六号苹果；七号梨子；八号梨子。

兜底 C 摘要：

> 四号南瓜；三号西红柿；一号辣椒；十号洋葱；八号辣椒；九号南瓜；二号西红柿；十一号洋葱。

## B 区逐树

每树只观察一次。8 帧预热后，感知输出独立确认的候选；mission 保留成熟且与二维码一致、
未补偿基座高度及三维距离符合 `b_limits` 的目标，按检测置信度中位数降序选择最多两个。
首次静止观察时一次性保存基座请求，再逐个 CLOSE/驻留、Store/松爪；同树成功抓取之间不回 Home。
每完成一个目标的抓取和 Store 工序，按识别品种计入一次统计。树末尾回 Home，再导航并切对侧 Look。
第一抓失败恢复一次 Home，确认成功后继续第二个冻结目标，不重新观察；恢复失败则跳过剩余目标。
最后一个目标失败已恢复 Home 时，不再重复调用树末尾 Home。

视觉识别确认后，在动臂抓取的同时异步播报品种并开始动臂（边动边播报）：

> 一号识别到成熟苹果，开始抓取。

放筐入仓（Store 工序）完成后，立即异步播报：

> 采摘完成。

无果实、无成熟目标或品种不符播报“跳过”，例如：

> 一号没有识别到果实，跳过。
> 一号识别到成熟梨子，跳过。

B/D 已识别但无有效深度或三维坐标的目标只记日志，不估算深度，不播报，也不抓取。
同树存在有效深度的成熟目标时，只处理有效目标；全部目标均被过滤时，静默跳过并按原流程回 Home。
完成观察后的真正空列表仍沿用“没有识别到果实，跳过”播报。A/C 开环规则不变。

导航失败也跳过当前树：

> 一号导航失败，跳过。

抓取动作失败且 Home 恢复成功时播报“继续下一个目标”；恢复失败时播报“跳过”。每次物理运动仍受新鲜反馈和 planner 保护。
这些语音不保证物理夹取或入筐成功。

## C 区逐项

严格按二维码/兜底序列推进，路线与左右侧使用现有规划结果。C_QR 可直达入口，通行 waypoint 按路径选择前进或倒车朝向。
导航与相应 Look 并行；导航失败不在未到达的位置识别/抓取，播报并跳过当前项：

> 四号导航失败，跳过。

视觉识别确认符合二维码要求后，在机械臂开始动作的同时异步播报（边动边播报）：

> 四号识别到成熟南瓜，开始抓取。

放筐入仓（Store 工序）完成后，立即异步播报：

> 采摘完成。

无目标、不成熟、种类不符均直接播报简短跳过台词，保存状态并推进下一项，不留在同一项反复观察或抓取：

> 四号没有识别到目标，跳过。
> 四号识别到不成熟南瓜，跳过。
> 四号识别到成熟西红柿，跳过。

## 流程结束与采摘汇总

`full` 遍历所有任务后，先从当前位置沿 C 区现有图规划前往 `C_top_waypoint_1`，
对齐航点 YAML 保存的 yaw，再调用汇总播报。收尾导航不提交机械臂动作，
导航失败不恢复 Home，不增加 mission 重试，重试交给导航层。
规划或导航最终失败时告警并直接汇总播报。其他入口仍在原结束位置播报：

> 任务流程结束
> 本次采摘记录
> 苹果两个
> 南瓜三个

若整场无有效采摘工序完成，则播报：

> 任务流程结束
> 本次没有采摘记录

说明：汇总中的数量基于**已确认完成全部抓取、放置与归位工序的软件记录**，并非通过传感器物理验证入筐的最终实际果实数。真实 Look/QR/Harvest/Home 姿态由用户配置；本次不改 planner 文件或编造角度。坐标转换、静止反馈、夹爪和轨迹传输仍须安全实机验收。
