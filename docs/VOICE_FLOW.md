# A/B/C 语音播报全流程

本文记录 `fruit_mission` 在 `mission_flow: full` 下的实际语音触发顺序，作为现场联调和裁判播报核对依据。文中的句子以当前代码生成的文本为准，不代表后续语音文案不能调整。

## 先看结论

当前完整流程的实际顺序不是“完成 A 后立即完成 B，再完成 C”。任务节点会先在 B 区二维码处保存 B 计划，再读取 C 区二维码并完成 C 区，最后返回 B 区按计划逐树作业：

```text
起点播报
  -> A 区作业
  -> B 区二维码播报
  -> C 区二维码播报
  -> C 区 8 项作业播报
  -> 返回 B 区
  -> B 区 8 棵树作业播报
  -> 任务结束播报
```

当前项目范围明确不实现前往收集更换区、收获汇总播报、导航返回起始区和到达起始区后的结束判定。`full` 流程的“任务结束”表示当前软件任务在 B 区作业完成后结束；上述四项是明确的范围裁剪，不列为待补功能。

## A 区

### 正常流程

比赛刚开始时先播报：

> Bobocup队开始比赛

A 区进入、到达作业点、识别到成熟目标、识别到未成熟目标、抓取成功和跳过目标，当前代码都没有正常播报。USB 侧相机确认成熟目标和抓取方向后，mission 发送一次对应方向的 `task_id=2`；下位机同时执行该方向的观察和开环抓取。收到 `callback_id=2, callback_status=0` 后，本次抓取直接完成并进入下一流程，不再切换 D435i `TREE` 模式或发送 `ArmTarget`。

### 异常流程

如果 A 区方向开环抓取返回执行失败，或 30 秒内没有返回终态，mission 会发送 `task_id=6` 返回 home。确认 `callback_id=6, callback_status=0` 后继续下一个任务；恢复失败时记录错误并停止 A 区流程。该恢复过程目前没有语音播报。

如果 A 区结束后的机械臂收缩姿态动作超时，会播报：

> A区结束机械臂收缩姿态动作超时，任务停止。

A 区进入失败或发送抓取方向命令前的感知模式切换失败目前直接返回失败，不追加语音。

## B 区

### B 区二维码

到达 B 区二维码、二维码计划有效后，先快速播报 8 个树位目标：

> 1苹果，2梨子，3苹果，4梨子，5苹果，6梨子，7苹果，8梨子。

这条播报进入异步语音队列。播报开始后立即继续机械臂收缩和后续导航，因此机器人可以边走边播报；音频仍由语音队列完整播放。

### B 区逐树

每棵树完成 50 帧识别后，感知节点以置信度最高的稳定目标确定整棵树为苹果或梨，并从最终稳定目标中丢弃另一品种，最多保留两个候选。mission 使用过滤后的稳定目标与当前树位的二维码目标比较，只在种类一致的成熟目标中抓取一个：只有一个成熟目标时直接选择；有两个时按 D435i 光学坐标系的 `abs(x) - y` 评分选择最高者，同分时保留感知侧原有排序。判断语音通过异步队列触发，不等待语音播放结束，也不播报成熟目标数量或抓取成功数量。一次抓取回调结束后执行收臂并前往下一棵树，不再尝试第二个目标。

识别品种与二维码一致且存在成熟目标时播报：

> B区B1，识别到苹果，和二维码一致，开始抓成熟苹果。

识别品种与二维码一致，但没有成熟目标时播报并跳过：

> B区B2，识别到梨子，和二维码一致，没有成熟梨子，跳过。

识别品种与二维码不一致时播报并跳过：

> B区B2，识别到苹果，和二维码不一致，跳过。

感知节点完成统计但没有输出稳定目标时播报：

> B区B2，没有识别到果实，跳过。

收到旧版或异常消息，导致同一棵树的最终稳定目标仍为不同品种，或类型无法解释时播报：

> B区B2，识别结果不一致，跳过。

等待感知节点最终结果超时时播报：

> B区B2，识别超时，跳过。

识别播报之后收到机械臂 `callback_status=2` 时播报：

> B区B2，机械臂执行报错，执行收臂。

30 秒内没有收到机械臂终态回调时播报：

> B区B2，机械臂执行通信超时，执行收臂。

上述两种情况都会发送 `task_id=7`；只有收臂完成才继续下一棵，收臂失败或超时仍按下方“任务停止”处理。

树位编号无效时播报：

> B区第9棵树编号无效，跳过。

树位导航失败时播报：

> B区B4导航失败，跳过。

单棵树完成后的机械臂收缩姿态动作超时时播报：

> B区B4机械臂收缩姿态动作超时，任务停止。

B 区全部树位完成后，如果最后的机械臂收缩姿态动作超时，播报：

> B区结束机械臂收缩姿态动作超时，任务停止。

## C 区

### C 区二维码

二维码计划有效后，先快速播报严格作业顺序：

> 1，12南瓜，2，11西红柿，3，10辣椒，4，9洋葱，5，5南瓜，6，6西红柿，7，7辣椒，8，8洋葱。

这条播报采用半异步等待：语音仍会完整播放，但任务节点只等待到预计播放结束前配置的提前量，随后立即开始机械臂收缩并进入下一项导航。音频播放由后台语音队列继续完成，不会被截断。

### C 区逐点成功

每一项到位、识别到二维码要求的成熟目标并抓取成功后播报。例如第 1 项识别到成熟南瓜：

> C区十二号位置，应该采南瓜。识别到成熟南瓜，抓取完成。

### C 区逐点跳过

没有识别到目标：

> C区十二号位置，应该采南瓜。没有识别到目标，跳过。

识别到同品种但未成熟：

> C区十二号位置，应该采南瓜。识别到未成熟南瓜，跳过。

识别到其他品种：

> C区十二号位置，应该采南瓜。识别到成熟辣椒，跳过。

识别到目标但下位机返回 `callback_status=2`：

> C区十二号位置，应该采南瓜。识别到成熟南瓜，机械臂执行报错。

30 秒内没有收到机械臂终态回调：

> C区十二号位置，应该采南瓜。识别到成熟南瓜，机械臂执行通信超时。

深度相机识别模式切换失败、没有形成可抓取的三维目标等情况，会使用相同的“识别结果 + 精简失败原因”结构。机械臂失败或通信超时后会发送 `task_id=7`，确认收臂完成后才推进下一项；收臂失败或超时则停止 C 区。语音中不重复播报“继续下一项”。导航 action 失败时，在识别前播报：

> C区十二号位置，应该采南瓜。导航重试。

如果当前位置不能用于恢复规划，还会播报：

> C区当前位置无法用于重新规划，C区任务停止。

无法根据当前位置规划安全路线时播报：

> C区十二号位置，应该采南瓜。无法根据当前位置规划安全路线，C区任务停止。

C 区二维码导航、区域上报、二维码模式切换、二维码识别姿态动作或二维码计划等待失败时，分别播报对应的停止原因，例如：

> C区二维码计划等待超时。

## 全流程结束

当 B 区逐树流程返回成功时，任务节点关闭感知模式并播报：

> 任务结束

这条语音表示当前软件任务状态机已完成 B 区流程并结束。当前项目明确不继续执行收集更换区、收获汇总播报、返回起始区或返航后的结束判定。

## 联调核对要点

- 起点必须听到 `Bobocup队开始比赛`。
- B 区二维码和 C 区二维码都必须在计划解析成功后播报一次，且内容与二维码顺序一致。两者都使用紧凑数字串词并采用较快语速；B 区二维码播报异步执行，允许边走边播报；C 区二维码播报完整播放，但任务按配置提前进入下一步。
- C 区每一项无论成功、未成熟、种类不符、无目标还是抓取失败，都必须播报并只推进一项任务游标。
- B 区每棵树在抓取前必须异步播报实际识别品种和二维码一致性；有成熟目标时播报开始抓取，没有成熟目标时明确播报并跳过，不播报目标数量。只有品种一致的成熟目标允许抓取，每棵树最多下发一个抓取目标。
- 当前没有 A 区正常逐点语音。收集更换区、收获汇总播报和返回起点属于明确裁剪范围，不列为待补功能。
