# A/B/C 语音播报全流程

本文记录 `fruit_mission` 在 `mission_flow: full` 下的实际语音触发顺序，作为现场联调和裁判播报核对依据。文中的句子以当前代码生成的文本为准，不代表后续语音文案不能调整。

正式 mission 的视觉目标与观察/二维码/收臂/恢复均调用 planner 服务；预设轨迹仍待补齐。
独立 camera/区域调试工具未迁移。当前到点使用夹爪 HOLD，
播报“开始抓”是代码文案，不证明完成夹取；本页描述源码时序，不是整机硬件验收记录。

## 先看结论

当前完整流程的实际顺序不是“完成 A 后立即完成 B，再完成 C”。任务节点会先在 B 区二维码处保存 B 计划，再读取 C 区二维码并完成 C 区，最后返回 B 区按计划逐树作业：

```text
起点播报
  -> A 区作业
  -> B 区二维码播报
  -> C 区二维码播报
  -> C 区 8 项作业播报
  -> 返回 B 区
  -> B 区 8 棵树作业播报
  -> 任务结束播报
```

当前项目范围明确不实现前往收集更换区、收获汇总播报、导航返回起始区和到达起始区后的结束判定。`full` 流程的“任务结束”表示当前软件任务在 B 区作业完成后结束；上述四项是明确的范围裁剪，不列为待补功能。

## A 区

### 正常流程

比赛刚开始时先同步播报，播报完成后才启动后续导航：

> 我们是重庆大学 bobocup 水果采摘队伍，现在开始采摘

A 区进入、到达作业点、识别成熟/不成熟目标、目标到位和跳过目标，当前代码都没有正常播报。
每个作业点按配置先左后右观察；执行 `left_look/right_look` 预设并确认完成，再切换单 camera
`DETECT`，等待成熟且深度有效的目标，经相机外参与实测关节 FK 转为机械臂基座坐标，
调用 `move_cartesian` 并等待执行结果。不再发送 `ArmTarget` 或等待目标 `callback_id=3`。
每个作业点左右处理结束后必须完成 `retract`，才能导航到下一点；A 区结束也必须确认收臂。

### 异常流程

方向预设或 planner 目标运动失败/超时直接停止 A，不叠加恢复运动。只有方向完成后的
DETECT 切换失败/未获得有效目标时才执行 `home` 预设，恢复成功才继续；失败则停止 A。
该过程没有语音。所有运动等待使用 `camera_extrinsic.yaml` 的 `service_timeout_sec`；
planner 超时/请求异常会尝试 STOP，但不证明硬件停稳。

每个作业点及 A 区结束收臂预设缺失、失败或超时，均播报动作失败、任务停止，禁止继续导航。
姿态名称由 `fruit_mission.yaml` 的 `arm_presets` 配置，实际角度轨迹由 planner YAML 定义。
启动脚本自动启动 planner-only launch，复用已有串口桥，不再等待旧 task/callback 端点。

A 区进入失败或发送抓取方向命令前的感知模式切换失败目前直接返回失败，不追加语音。

## B 区

### B 区二维码

到达 B 区二维码、二维码计划有效后，先快速播报 8 个树位目标：

> 1苹果，2梨子，3苹果，4梨子，5苹果，6梨子，7苹果，8梨子。

这条播报进入异步语音队列。播报开始后立即继续机械臂收缩和后续导航，因此机器人可以边走边播报；音频仍由语音队列完整播放。

B 区二维码计划等待超过 20 秒时不停止任务，而是使用配置的兜底计划并按正常链路播报：

> 1梨子，2苹果，3梨子，4苹果，5苹果，6苹果，7梨子，8梨子。

### B 区逐树

每棵树完成 50 帧识别后，感知以置信度最高的稳定目标确定整树品种，丢弃另一品种，最多保留两个候选。
mission 比较二维码品种，并只选择一个成熟目标；两者均成熟时按原图像素
`abs(pixel_x - image_width / 2) - pixel_y` 取最高者，同分保留原排序，不用三维米制坐标评分。
播报异步入队，不等待音频结束，不播报数量。一次 planner 目标运动成功后执行 `retract` 预设，
再去下一棵树，不尝试第二个目标。

识别品种与二维码一致且存在成熟目标时播报：

> B区B1，识别到苹果，和二维码一致，开始抓成熟苹果。

识别品种与二维码一致，但没有成熟目标时播报并跳过：

> B区B2，识别到梨子，和二维码一致，没有成熟梨子，跳过。

识别品种与二维码不一致时播报并跳过：

> B区B2，识别到苹果，和二维码不一致，跳过。

感知节点完成统计但没有输出稳定目标时播报：

> B区B2，没有识别到果实，跳过。

收到旧版或异常消息，导致同一棵树的最终稳定目标仍为不同品种，或类型无法解释时播报：

> B区B2，识别结果不一致，跳过。

等待感知节点最终结果超时时播报：

> B区B2，识别超时，跳过。

识别播报后 planner 目标运动返回失败（`arm_callback_failed`）时播报：

> B区B2，机械臂执行报错，任务停止。

目标服务等待超时（当前配置 30 秒，`arm_callback_timeout`）时播报：

> B区B2，机械臂执行通信超时，任务停止。

上述两种情况直接停止任务，不叠加收臂运动。正常完成或感知跳过后，只有 `retract` 服务确认完成才继续下一棵。

树位编号无效时播报：

> B区第9棵树编号无效，跳过。

树位导航失败时播报：

> B区B4导航失败，跳过。

单棵树完成后的机械臂收缩姿态动作超时时播报：

> B区B4机械臂收缩姿态动作超时，任务停止。

B 区全部树位完成后，如果最后的机械臂收缩姿态动作超时，播报：

> B区结束机械臂收缩姿态动作超时，任务停止。

## C 区

### C 区二维码

二维码计划有效后，先快速播报严格作业顺序：

> 1，12南瓜，2，11西红柿，3，10辣椒，4，9洋葱，5，5南瓜，6，6西红柿，7，7辣椒，8，8洋葱。

这条播报采用半异步等待：语音仍会完整播放，但任务节点只等待到预计播放结束前配置的提前量，随后立即开始机械臂收缩并进入下一项导航。音频播放由后台语音队列继续完成，不会被截断。

C 区二维码计划等待超过 20 秒时同样不停止任务，而是播报并执行以下兜底顺序：

> 1，4南瓜，2，3西红柿，3，1辣椒，4，10洋葱，5，8辣椒，6，9南瓜，7，2西红柿，8，11洋葱。

### C 区逐点到位

每项识别到二维码要求的成熟目标且 planner 运动成功后播报。例如第 1 项：

> C区十二号位置，应该采南瓜。识别到成熟南瓜，机械臂已到目标点。

### C 区逐点跳过

没有识别到目标：

> C区十二号位置，应该采南瓜。没有识别到目标，跳过。

识别到同品种但不成熟：

> C区十二号位置，应该采南瓜。识别到不成熟南瓜，跳过。

识别到其他品种：

> C区十二号位置，应该采南瓜。识别到成熟辣椒，跳过。

识别到目标但 planner 运动返回失败：

> C区十二号位置，应该采南瓜。识别到成熟南瓜，机械臂执行报错。

目标服务等待超时（当前配置 30 秒）：

> C区十二号位置，应该采南瓜。识别到成熟南瓜，机械臂执行通信超时。

深度相机识别模式切换失败、没有形成可抓取的三维目标等情况，会使用相同的“识别结果 + 精简失败原因”结构。机械臂失败或通信超时后停止 C，不叠加收臂运动；正常完成或感知跳过后必须确认 `retract` 完成才推进下一项。语音中不重复播报“继续下一项”。导航 action 失败时，在识别前播报：

> C区十二号位置，应该采南瓜。导航重试。

如果当前位置不能用于恢复规划，还会播报：

> C区当前位置无法用于重新规划，C区任务停止。

无法根据当前位置规划安全路线时播报：

> C区十二号位置，应该采南瓜。无法根据当前位置规划安全路线，C区任务停止。

C 区二维码导航、区域上报、二维码模式切换或二维码识别姿态动作失败时，仍播报对应的停止原因。只有二维码计划等待超时会改用上述兜底计划并继续。

## 全流程结束

当 B 区逐树流程返回成功时，任务节点关闭感知模式并播报：

> 任务结束

这条语音表示当前软件任务状态机已完成 B 区流程并结束。当前项目明确不继续执行收集更换区、收获汇总播报、返回起始区或返航后的结束判定。

## 联调核对要点

- 起点必须先听到 `我们是重庆大学 bobocup 水果采摘队伍，现在开始采摘`，播报完成后才能启动导航。
- B 区二维码和 C 区二维码都播报一次最终计划：20 秒内解码成功时使用二维码顺序，超时时使用配置的兜底顺序。两者都使用紧凑数字串词并采用较快语速；B 区播报异步执行，允许边走边播报；C 区播报会完整播放，但任务按配置提前进入下一步。
- C 区每一项无论成功、不成熟、种类不符、无目标还是抓取失败，都必须播报并只推进一项任务游标。
- B 区每棵树在抓取前必须异步播报实际识别品种和二维码一致性；有成熟目标时播报开始抓取，没有成熟目标时明确播报并跳过，不播报目标数量。只有品种一致的成熟目标允许抓取，每棵树最多下发一个抓取目标。
- 当前没有 A 区正常逐点语音。收集更换区、收获汇总播报和返回起点属于明确裁剪范围，不列为待补功能。
