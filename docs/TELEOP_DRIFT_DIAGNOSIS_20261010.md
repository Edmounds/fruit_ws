转换器当前直接采用阈值截断：

```text
abs(axis) < 0.1: velocity = 0

```

因此，轴值越过 `0.1` 时，线速度从零直接跳到约 `0.04 m/s`。

当前转换器没有按住使能按钮的条件，因此没有按钮按下也能移动。

## 超时与串口证据边界

已检查系统安装的 `twist_mux/topic_handle.hpp`。
`timeout: 0.5` 用于判定输入优先级是否过期。
输入回调收到消息并获得优先级时才转发速度。
该参数不能作为“0.5 秒后主动发送零速度”的保证。
本次 20 Hz 输入没有过期，因此缩短 mux 超时也不能消除新鲜的残值指令。

`joy_convert_node.cpp` 没有输入失联定时停车逻辑。
串口桥负责转发，未实现底盘指令失联停车策略。
下位机是否具有独立速度指令超时，仍需检查固件。
这些是已识别的保护缺口，不能当作本次异常片段的已证实触发原因。

串口协议对线速度和角速度分别取反。
已核对构建目录生成的绑定，映射与 source YAML 一致。
取反不会把零变成非零。

本次桥日志只有 INFO，没有 `[MCU TX DECODED]` 底盘发送细节。
`waypoints_maker.sh --debug` 启动录包并调整输出过滤，但没有传入桥 `log_level:=debug`。
因此本次不能证明零速度包的发送完成时间或下位机接收时间。

## 终端提示的含义

- 开头两条 `[ros2run]: Process exited with failure 1` 来自已有节点探测命令。
  脚本随后按“未发现节点”分支启动对应组件，不能把它们视为运行中节点崩溃。
- `Drop TX packet before serial is ready` 发生在启动早期。
  串口约一秒后连接，异常前进发生在两分钟后。
- Point-LIO 的 `doesn't exist` 来自 `parameters.cpp::open_file()` 打开调试文件失败。
  此字符串不证明 Point-LIO 源目录不存在，里程计随后正常发布。
- 初始丢弃点云和 IMU 初始化提示属于启动阶段。
  随后出现 `stable odom origin is ready`。
- MCAP 提示缺少 action feedback 类型定义。
  该话题没有消息，Joy、Twist 和 Odometry 均能正常离线解码。
- Ctrl-C 后所有所列节点正常退出，会话退出码为零。

## 建议修复与验证顺序

1. 在车轮离地或底盘驱动禁用时，观察完全未触碰的输入。
   同时比较 Linux 原始 ABS_Y、`/joy.axes[1]` 和最终速度。
2. 比较 USB 与蓝牙连接，并用另一只手柄复测。
   确认异常属于手柄、连接驱动还是校准后，再决定校准或更换。
3. 软件死区必须覆盖实测回中残值，并留出余量。
   本次残值达到 `0.195`，原 `0.1` 明显不足。
   `0.20` 余量很小，增大死区也不能保证阻止继续增长的输入异常。
4. 可采用连续死区映射，避免跨阈值时速度突然跳变。
   如采用按住使能按钮，需要明确按钮和导航交接语义。
5. 输入失联停车和固件速度超时需要分别验证。
   新鲜但错误的输入不会触发普通消息超时。
6. 记录下位机接收目标速度和实测轮速，再分析归零后的停车距离。
   ROS 发布零速度不能替代硬件停稳确认。
