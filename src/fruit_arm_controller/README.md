# fruit_arm_controller：上位机直接控制机械臂方案

状态：设计草案，仅有文档，尚无控制代码或 ROS 包构建文件。
目录已建立，但当前不会被 colcon 注册为可运行包。
本次不替换正在使用的 `fruit_arm_planner`，不修改通信桥或下位机。

目标是让上位机负责解算、运动参考、执行节奏、到位容差和夹爪动作。
下位机只应用当前执行器命令，采集反馈，并保留基础硬件保护。
电机和舵机内部的高速伺服环继续由驱动器执行。

```mermaid
flowchart LR
    M[mission / 原控制台] -->|原服务与话题| U[fruit_arm_controller]
    U -->|当前电机与舵机设定值| B[通信桥]
    B -->|传输命令数据| L[下位机硬件适配]
    L --> D[电机 / 舵机内部伺服环]
    D -->|实测反馈| L
    L -->|执行器反馈数据| B
    B --> U
    U -->|原遥测 / 兼容状态 / 服务结果| M
```

新方案不再向下位机发送整条轨迹，或等待轨迹装载后发送启动 Mode。
上位机按周期发送当前设定值，终点容差和完成状态由上位机计算。
命令帧封装、CRC、ACK、重发和传输队列归通信桥管理。
数据契约仍要求新命令替换旧命令，并禁止 STOP 后重放旧运动命令。

## 已确定的设计范围

- 保持 `MoveArmCartesian`、`MoveArmJoints`、`ExecuteArmPreset` 的类型和端点。
- 保持 Home、STOP、ESTOP、预设重载和现有调试输入。
- 保持原 `ArmTelemetry` 类型、四轴角度语义和真实 TCP 定义。
- 复用现有 FK/IK、`JointTransformer` 和 PTP/LIN 数学实现。
- 复用现有 `presets`，保留坐标、时长、夹爪动作和航点 `linear`。
- 不设置运动到位的业务超时，不自动重试或恢复抓取。
- 保留输入验证、反馈新鲜度、STOP、ESTOP 和本地失联保护。

## 已确认的硬件结构

当前 API 表示四个姿态轴：底座偏航、大臂、小臂、腕部。
夹爪是独立执行器，不占用 `joint_4`。
用户已确认三台关节电机控制底座旋转、大臂和小臂。
腕部和夹爪使用两个舵机，总计五个执行器。
因此，四个姿态轴加独立夹爪的数据结构可以完整保留。
具体电机和飞特舵机型号仍需确认，旧固件型号不能替代当前硬件信息。

本目录描述未来架构，不改变旧包的现行执行结果契约。
实施新方案后，动作完成的证据来源将从 MCU `COMPLETED` 改为上位机实测判断。
