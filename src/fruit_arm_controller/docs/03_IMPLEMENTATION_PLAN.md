# 03. 最小实施计划与待确认事项

本次交付是文档草案，以下步骤尚未执行。
此目录暂不添加 package.xml、节点、launch、依赖或 rosidl 文件。
预设及标定仍由原包维护，避免设计阶段产生第二份运行配置。

## 1. 先确认硬件，不先写控制器

用户已确认三台关节电机加两个舵机，共五个执行器。
底座旋转、大臂、小臂和腕部对应四个姿态轴，夹爪独立。

| 待确认项 | 当前证据 | 对实现的影响 |
| --- | --- | --- |
| 关节电机品牌、型号及固件 | 旧配置使用达妙命名，不能确认当前全部型号 | 模式、速度字段、力矩量纲和停机方式 |
| 腕部和夹爪飞特型号 | 旧配置记载其他舵机控制范围 | 位置范围、反馈、速度、加速度和负载能力 |
| 固定硬件零位与传动耦合 | 当前 JointTransformer 已有 Q3 耦合 | 厂商原始读数如何保持现有 hardware 语义 |
| CLOSE 完成判据的测量阈值 | 已确定首次接触或完全闭合均视为动作成功 | 标定接触证据和闭合位置，不判断水果存在 |
| 接触后的持续抓紧 | 已确定首次接触即完成，之后继续抓紧 | 舵机能力、限力、HOLD 与 STOP 的作用 |
| 串口和厂商总线吞吐量 | 旧桥曾配置 115200 baud | 可用控制频率与反馈频率 |
| 本地停止与失联策略 | 重力负载可能不能直接失能 | 可验证 STOP、ESTOP 与重启状态 |
| 到位容差和速度约束 | 当前 API 未携带这些参数 | 新 config/control.yaml 的标定值 |

这些事项可以留在文档草案中，但在接口编码和带载运行前必须解决。
力矩反馈能力不自动意味着应采用力控模式。
首版已确认采用位置控制，加上上位机到位判断。
后续只有明确需要时，再设计阻抗或力控功能。

## 2. 创建最小 ROS 包

确认数据契约后，使用 ROS CLI 创建 `ament_python` 包。
第一版复用 `fruit_arm_planner` 的数学模块，不复制第二套 IK。
原包可以作为算法依赖保留，但不能同时启动其旧执行节点。
不引入 MoveIt、ros2_control 或额外控制框架作为本次默认前提。

拟议的最小结构：

```text
fruit_arm_controller/
  README.md
  docs/
  package.xml                       # 实施时创建
  setup.py / setup.cfg / resource/   # 实施时创建
  config/
    arm_presets.yaml                # 实施时迁移原内容
    control.yaml                    # 执行器能力、频率和到位配置
  launch/
    fruit_arm_controller.launch.py
  fruit_arm_controller/
    arm_controller_node.py          # 原 API、状态、周期执行与到位判断
```

首版优先一个清晰节点，不引入插件体系、工厂或通用机器人驱动抽象。
消息和服务类型从现有接口包导入，帧封装留给桥。
按职责确有需要时再拆出小文件，不先搭空模块。
launch 遵循 `template.launch.py`，包括 `use_sim_time` 和源码配置路径。
真实硬件执行必须使用单调时钟，不让仿真时钟暂停改变失联保护。

## 3. 配置迁移与上层兼容

1. 保存实施时原 YAML 内容及 Git 差异，保留全部用户标定。
2. 将原 geometry、joint_mapping、planning 和 presets 逐字迁入新源码配置。
3. 用原校验与离线规划检查预设，不把不可达旧值自动改成另一姿态。
4. 新增独立控制配置，填写测量后的执行器能力和容差。
5. 更新 mission 外参配置中的 `arm_config_path`。
6. 更新控制台的配置路径及新下发诊断订阅。
7. 保留原服务与 telemetry 类型，不更改 mission 的采摘顺序。

旧 mode 缓冲参数在新节点中明确不生效。
新 `control.yaml` 的具体键名在硬件确认后冻结，不提前假定当前型号范围。
实施阶段更新 AGENTS.md、原 API 文档、通信文档和根启动脚本。
这些更新必须明确新旧契约切换，不能把本草案描述成已部署行为。

## 4. 建立新下位机数据通路

先定义 `ArmActuatorCommand`、`ArmActuatorFeedback` 和 `ArmActuatorControl` 的 ROS 消息。
定义放在 `fruit_hardware_interfaces/msg/`，协议字段映射由桥管理。
桥的 protocol.yaml 修改需要重新生成和构建，不能手改生成文件。
下位机同步实现厂商单位换算、当前目标应用、反馈和本地保护。

新通路不再使用 Header → Points → Mode 的批量装载流程。
旧通路与新通路不得同时控制硬件。
下位机上电只初始化和反馈，不自动执行旧 Home 或水果工序。
使能前必须取得当前位置，并设置无跳变初始目标。
新节点启动不自动 Home，不自动解除硬件急停。

## 5. 实现上位机执行

先接入真实反馈与兼容 ArmStatus/ArmTelemetry 输出。
再接入占用权、PTP/LIN 参考、周期设定值、到位窗口及夹爪动作。
最后接入预设顺序和服务完成结果。

参考首点必须来自实测，不能把缺失轴、无效速度或历史反馈补成零。
规划无效则不下发任何运动目标。
执行期间保持 STOP/ESTOP 可响应。
收到硬件故障后停止当前业务，不增加自动重试或恢复 Home。
没有实测完成证据，服务不得返回 success=true。

## 6. 验收证据

| 阶段 | 要验证的可观察行为 | 手段 |
| --- | --- | --- |
| 数学复用 | 同配置 FK/IK、Q3 映射、刚性 TCP 与原包一致 | 复用现有数学检查及离线数值计算 |
| 无硬件数据通路 | 原服务字段、状态类型、有效反馈和失败响应 | 独立 ROS domain 的离线执行脚本 |
| 桥与 MCU | 更新值替换、重复幂等、STOP 优先及旧会话不能复活 | 独立协议检查与记录 |
| 实机无载 | 使能无跳变、每轴方向单位正确、实际到位窗口 | 人工安全台架会话 |
| 夹爪接触 | OPEN/CLOSE/HOLD、接触判据和重复目标行为 | 人工台架标定 |
| 时序 | 链路带宽、命令年龄、轴间偏差、停止反应及失联保护 | 同步记录命令编号、反馈样本与时间 |
| 上层联调 | Look 停稳、真实 TCP、目标 CLOSE、Store/Home 的原 API | 经确认的人工硬件联调 |

不添加源码字符串测试，不使用深度 mock 冻结节点内部状态。
不通过自动运行硬件控制台或运动服务完成验证。
无载与带载测试必须由操作者确认条件并执行。

验收不能只证明 ROS publish 或 ACK 成功。
必须证明反馈来自执行器，命令实际应用，且上位机判断了真实完成。
普通未到位采用独立有限等待，失败后释放服务占用，不永久锁止后续操作。
业务失败与硬件故障必须明确分类，不能把空抓伪装成硬件故障锁。
失联、本地保护及显式 STOP 仍必须终止危险运动。

## 7. 部署与日志

机器人部署仍在 main，不切换分支运行不同控制版本。
切换前确认实测停稳，再停止旧 planner、控制台及 mission。
同一会话只能有一个串口桥和一个机械臂控制源。
重新构建接口和消费者，加载干净运行环境后启动新方案。

控制节点日志沿用会话日志目录，由根启动脚本接入。
保留 `action_id`、`command_seq`、反馈 `sample_seq` 和 MCU `boot_id` 关联。
记录到位误差、夹爪判据、命令年龄及本地保护原因。
高频数据写专用日志，不刷屏输出原始十六进制帧。

回退也必须停稳并切换整套接口、桥与 MCU 模式。
不能只启动旧 planner，而让下位机继续接收新周期数据。
