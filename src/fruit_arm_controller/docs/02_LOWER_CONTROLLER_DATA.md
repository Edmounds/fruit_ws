# 02. 与下位机的数据契约

本文件只定义数据和行为，不定义字节布局、包头、CRC、ACK 或重发算法。
以下消息名称、话题和字段为拟议契约，不是现有 ROS 接口。
未来 ROS 定义放入 `fruit_interfaces`，不在控制包重复定义。

## 1. 边界与统一单位

上位机发送当前各执行器目标，下位机调用驱动器并返回实际读数。
下位机不接收 Cartesian XYZ、预设名、容差或业务完成期限。
下位机不返回 trajectory COMPLETED，不拥有 mission 或夹取状态机。

姿态轴编号固定为 `joint_1`、`joint_2`、`joint_3`、`joint_4`。
分别表示底座、大臂、小臂、腕部，独立夹爪标为 `gripper`。
物理 CAN/舵机 ID 由硬件适配配置，禁止把它们隐式当模型轴编号。

| 数据 | 单位与语义 |
| --- | --- |
| DM 轴位置 | rad，实际电机轴原生位置；上位机负责机械映射 |
| DM 轴速度 | rad/s，实际电机轴方向 |
| 速度上限 | rad/s，非负，区别于有符号参考速度 |
| 加速度上限 | rad/s²，非负，仅能力支持时有效 |
| 电机力矩 | N·m，输出轴侧，能力和换算经确认后才有效 |
| 电流 | A，不自动等同于力矩或夹持力 |
| 温度、电压 | °C、V，设备不支持时标无效 |
| 样本年龄和生存期 | ms，以单调时钟测量 |
| 夹爪位置 | 原生位置计数，需确认飞特型号范围及方向 |
| 夹爪速度 / 加速度 | 原生计数/s、计数/s²，具体换算需标定 |
| 腕部 FTS 位置 | 原生计数 0..4095；零位 2047，上位机做腕角换算 |

硬件角不是旧 MCU 已做过 FK/耦合补偿的逻辑关节角。
NUC 完成模型映射、DM 传动耦合和 FTS 腕角到刻度换算。
MCU 只做厂商驱动寄存器与规定原生单位的转换，不做机械补偿。
转换表必须明确零点、方向、传动比和轴类型，并做双向验证。
若厂商数值与现有 API 硬件角不同，选择一个适配边界完成转换，不双重补偿。

## 2. 周期命令 ArmActuatorCommand

建议端点：`/fruit_hardware_bridge/arm/actuator_command`，上位机发布，桥接收。
一条逻辑命令包含四个姿态轴和夹爪的当前设定值。
这样四轴使用同一命令快照，减少单独话题间的顺序依赖。

| 字段 | 拟议类型 | 要求 |
| --- | --- | --- |
| `session_id` | uint64 | 本次控制会话，MCU 重启或新会话须重新建立 |
| `command_seq` | uint64 | 会话内严格递增，不复用，接近溢出时建立新会话 |
| `action_id` | uint32 | 上位机业务动作编号，仅诊断，MCU 不用它判断完成 |
| `lease_ms` | uint32 | 最新运动命令允许保持的时间，基础失联保护使用 |
| `dm_commands` | 固定三项 | 底座、大臂、小臂的电机轴目标，禁止缺轴或重复轴 |
| `wrist_command` | 一项 | FTS ID1 原生位置、速度及支持的加速度/电流参数 |
| `gripper_command` | 一项 | 独立夹爪设定值，不占用 joint_4 |

每台 DM 命令包含：

| 字段 | 含义 |
| --- | --- |
| `mode` | 首版 POSITION，适配具体电机位置模式 |
| `position_rad` | 当前电机轴原生位置设定值，有限且在电机轴限位内 |
| `velocity_rad_s` | 有符号参考速度，模式支持时才应用 |
| `velocity_limit_rad_s` | 非负速度上限，厂商位置速度模式可使用此项 |
| `acceleration_limit_rad_s2` | 可选加速度上限，能力不支持时不启用 |
| `field_mask` | 明确可选字段是否有效，禁止用数值 0 表示“不支持” |

所有参与模式的字段必须校验有限性、范围及执行器能力。
模式不支持时明确拒绝命令并报告原因，不静默忽略后继续执行。

腕部和夹爪命令包含 `position_count`、`speed_limit_count_s`、支持的加速度上限和电流参数。
FTS ID1 零位 2047，范围 0..4095，机械安全范围另行标定。
FTS ID2 业务张开目标 400，闭合目标 0，接触后追加闭合 50 的目标由上位机算好。
电流参数的目标/限制语义正在最后一轮确认，厂商编码与 A 的换算必须验证。
它没有 OPEN/CLOSE 业务枚举，下位机不负责把“闭合”展开成探测工序。
OPEN/CLOSE/HOLD 在上位机转换为具体设定值，HOLD 重用有效保持目标。
首次接触后的持续抓紧也归上位机，同一个夹爪命令通路继续更新设定值。
MCU 不判断首次接触，也不因服务完成自动停止夹爪或执行松动补抓工序。
HOLD 保留上位机的当前夹爪策略，不取消持续抓紧。
普通 STOP 由上位机选择冻结夹爪位置，MCU 本地 STOP 必须能停止原主动目标。
断链时的本地夹爪保持行为还需结合型号能力明确，不能假设能继续执行上位机追紧策略。
厂商支持的负载上限可以作为可选保护字段，不能称为未经标定的力设定值。
厂商速度寄存器中的 0 可能有特殊含义，必须由适配层验证，不能默认代表停止。

ROS 周期数据建议 VOLATILE、KEEP_LAST、depth=1，防止重连后重放缓存。
可靠性按桥的实际能力确定，但 RELIABLE 本身不保证最新值替换。
独立控制操作不能被周期目标覆盖，STOP 需要可靠且优先的传输。
兼容状态输出保留现有 VOLATILE 语义，不创建新的 latched 运动命令。

## 3. 最新值、重复值和应用确认

周期命令采用“最新有效值替换旧值”的语义，不排队执行所有历史样本。
桥不得沿用当前逐包无限积压的队列语义发送周期运动命令。
已被更新值替代的旧值不需要继续重发，具体实现归通信桥。

MCU 验证会话、顺序、命令完整性和本地保护状态后，更新当前命令快照。
重复 `command_seq` 不重新触发舵机动作，也不刷新运动生存期。
更旧的序号不执行，不因补发而拉回旧位置。
同一序号内容不同属于无效命令，报告数据不一致。
MCU 的总线刷新可以重复当前驱动器设定值，不等于接收了一条新上位机命令。

`last_applied_command_seq` 指所有必要驱动器写入操作已成功提交的最新快照。
若任一轴写入失败，回报故障，并禁止把整组命令标成应用成功。
各厂商总线实际写入不一定同时完成，需要记录并测量轴间应用偏差。
这个字段不是电机到位确认，也不是传输 ACK。
完整的效果证据仍来自每轴实测位置、速度和上位机容差判断。

桥须限制接收至应用的命令年龄，不能让延迟新序号刷新失联计时。
NUC 和 MCU 不要求同步时钟，不能直接相减它们的绝对时间戳。
实施时由桥确定年龄预算或时间同步办法，并证明旧命令会被丢弃。
若无法提供端到端年龄上界，本草案不能宣称周期控制已可部署。

## 4. 原始反馈 ArmActuatorFeedback

建议端点：`/fruit_hardware_bridge/arm/actuator_feedback`，桥发布，上位机订阅。
反馈持续发布，不依赖业务动作是否正在运行。
反馈只含设备事实，不携带任务进度、到位容差或预设状态。

| 字段 | 拟议类型 | 含义 |
| --- | --- | --- |
| `boot_id` | uint64 | MCU 启动标识，变化使旧会话立即失效 |
| `session_id` | uint64 | 当前已接受的控制会话，没有会话时标未建立 |
| `feedback_seq` | uint64 | 本次启动内递增，帮助识别重复回传 |
| `last_applied_command_seq` | uint64 | 已应用命令快照的编号 |
| `last_applied_control_seq` | uint64 | 已执行控制操作的编号 |
| `ready` | bool | 初始化完成且必要执行器可用，不代表姿态已 Home |
| `enabled_mask` | 位掩码 | 执行器使能状态 |
| `stop_latched` | bool | 旧会话运动已被停止，属于顺序屏障，不要求人工解锁 |
| `fault_flags` | 位掩码 | 统一硬件事实，含失联、总线失败、过流等已定义类别 |
| `dm_feedback` | 固定三项 | DM 原生电机轴实测数据 |
| `wrist_feedback` | 一项 | FTS ID1 原生刻度及反馈数据 |
| `gripper_feedback` | 一项 | 独立夹爪实测数据 |

每台 DM 反馈包含 `position_rad`、`velocity_rad_s`、可用的 `torque_nm`、
`current_a`、`temperature_c`、`voltage_v`，以及 `valid_mask` 和 `device_fault_code`。
必须附带 `sample_seq`、`sample_age_ms` 和 `online`。
`sample_seq` 只在获取新设备样本时推进，不随 ROS 转发推进。
`sample_age_ms` 表示 MCU 打包时该设备数据的年龄，桥还需考虑后续传输延迟。

腕部与夹爪反馈使用 `position_count`、`velocity_count_s` 与电流或力矩/负载读数。
原四轴硬件角和模型角由上位机统一反算，不能把 FTS 刻度填入原 rad 字段。
厂商无量纲负载只回传原始有符号值与明确单位说明，不标为 N·m。
厂商不提供某项时，标无效，不把 0 填为真实测量值。
用户确认全部电机及舵机具备力矩反馈，实际量纲和厂商估算方式待型号核实。
夹爪接触检测读取有效力矩或经标定的等效负载，不使用无效字段凑接触证据。
姿态轴速度可以由上位机从真实位置及样本间隔估计，但必须经过有效性校验。
重复样本不能参与速度差分或到位稳定窗口。

`ready=false`、重启、样本失效或硬件锁定时，上位机停止推进业务运动。
无效反馈不能包装为正常兼容遥测。
没有新设备样本时，不重复发布旧有效快照来刷新消费者的新鲜度。
若需发布故障兼容状态，其无效位置和速度不得伪造为零或标记为正常 IDLE。
本地保护码与现有 `ArmStatus.error_code` 不是天然一一对应。
实施时建立明确映射，未知错误保留原始信息并返回失败。
不能为方便兼容，把失联统一伪装为既有任务 ERROR_TIMEOUT。

## 5. 控制操作 ArmActuatorControl

建议端点：`/fruit_hardware_bridge/arm/actuator_control`，独立于周期命令。
字段为 `session_id`、`control_seq` 和 `operation`。
首版操作为 `BEGIN_SESSION`、`ENABLE`、`STOP`，数值编码待协议定义。
原上层 emergency_stop 端点也转换为 STOP，不新增下位机 ESTOP 数据操作。

| 操作 | 下位机最小行为 |
| --- | --- |
| BEGIN_SESSION | 停稳和保护允许时建立新会话，清除旧命令，不自动运动 |
| ENABLE | 执行器使能，不重置物理零位，不自动 Home |
| STOP | 优先阻断旧目标刷新，进入经验证的本地停止/保持状态 |

STOP 后锁住旧会话运动命令，不能靠迟到的 command_seq 重新启动。
恢复必须实测停稳，再建立新会话并从当前实测位置生成新参考。
故障原因消失、反馈有效并实测停稳后，上位机可自动为新请求建立新会话。
恢复条件须连续满足 200 ms，初始参数可配置。
本地过流、过温等驱动器保护继续独立工作，不靠 ROS 或上位机存活保证。

桥必须使 STOP 优先于运动命令，并丢弃旧运动积压。
下位机锁定机制仍需阻止传输途中已经发出的旧命令生效。
无需桥理解水果或 IK，但桥必须满足该数据顺序契约。
具体 ACK、优先队列和重发设计不在控制包内实现。

有重力负载时，停止策略不能默认等于切断所有电机力矩。
保持当前位置、受控停机或失能的选择，需要按实机驱动器能力验证。
MCU 本地 STOP 可以调用驱动器停机功能，不需要重建上位机轨迹。
没有可验证的本地停止手段，就不能以“MCU 只执行”作为删掉保护的理由。

## 6. 失联保护和业务超时的区别

MCU 不判定到位或抓取的业务超时。
上位机对到位等待采用独立有限窗口，超出窗口返回非硬件失败，不永久锁止后续请求。
后续物理运动仍要求有效反馈和实测停稳，硬件失联不归类为普通业务超时。
`lease_ms` 只用于防止上位机断开后仍持续执行旧速度或力矩目标。
它是硬件失联保护，仍需要 MCU 独立执行。
桥重发、MCU 本地总线刷新及重复命令均不能无限延长旧目标生存期。

失联保护触发后锁住旧会话，执行本地停止策略并报告事实。
上位机若仍存活，结束当前动作并返回失败，不自动恢复或重抓。
生存期数值须由调度、串口延迟和硬件停机测量确定，本文不指定毫秒数。

## 7. 吞吐量与部署条件

设计时必须同时预算下发、反馈和桥的附加流量。
对于 8N1 串口，每字节约占 10 bit。
全双工链路分别计算 TX 和 RX 占用，不能误把双向字节简单相加当作单方向上限。
若实际通道半双工或共享总线，则按总占用计算。

单方向占用近似为 `频率 × 完整帧字节数 × 10 / 波特率`。
例如 115200 baud 下，200 字节反馈以 50 Hz 回传约占该方向 87%。
这个例子不代表最终帧长度，只说明字段丰富时不能未经测量就确定 50 Hz。
必须预留 STOP、状态操作、其他机器人流量和重发余量。

要求测量命令延迟上界、反馈年龄、丢帧、轴间应用偏差和 STOP 反应时间。
用户已选择首版命令和反馈帧各以 20 Hz 为目标，各执行器样本年龄仍独立检查。
需要的流控、更新值替换和优先级可能要求通信桥改动。
新包单独实现无法绕过现有桥的队列能力限制。
