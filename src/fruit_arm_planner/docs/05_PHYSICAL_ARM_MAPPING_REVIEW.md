# 实机四轴角度与解算链路核查

本记录依据当前 `fruit_arm_planner` 源码、`config/arm_presets.yaml` 和实机结构描述。下文的 `h1..h4` 是下位机命令/反馈角，`q1..q4` 是几何解算角；公式中的角度可以统一使用度或弧度，实际 ROS 轨迹消息使用弧度。本文是静态与数值核查，尚无固件实现或实机测量来证明电机编码器的零位和正方向。

## 1. 实机与算法分别怎样定义角度

```text
侧视图：+X 向前，+Z 向上；基座偏航 h1 使整幅侧视图绕 Z 轴旋转。

                         +Z
                          ^
                          |      E ---------- W -- T
                          |      |  小臂 h3=0    腕部 h4=0
                          |      |  水平向前     与小臂同向
                          |      |  大臂 h2=0
                          |      |  竖直向上
                          |      O  肩轴，Q2/Q3 电机在根部
                          |      :  Q3 经同步带驱动 E 处的小臂关节
                          +----------------------------------------> +X
```

上图表示三个硬件角均为零时的侧视姿态。角度关系是：

```text
角度                  相对谁                         硬件零位
大臂 A                水平向前                       h2=0 时 A=+90°
小臂 B                水平向前，不随大臂改变         h3=0 时 B=0°
末端俯仰 P            水平向前                       P=B+腕部相对角
腕部相对角 W          小臂                           h4=0 时 W=0°（待实机确认）

算法内部：q2=A，q3=B-A，q4=P-B。
因此 B=q2+q3，P=q2+q3+q4。
```

大臂硬件角的正方向为后仰，当前 `q2 = h2 + 90°` 正好表达这一点：`h2=-90°` 是大臂水平向前，`h2=0°` 是竖直向上，`h2>0°` 是继续向后仰。若小臂和腕部的硬件正方向也与上述角度正方向一致、且水平/同向时反馈为零，期望的双向映射为：

```text
理论角 -> 硬件角：h1=q1，h2=q2-90°，h3=q2+q3，h4=q4
硬件角 -> 理论角：q1=h1，q2=h2+90°，q3=h3-q2，q4=h4
末端实际俯仰：P=h3+h4
```

`h3=0°` 表示小臂水平向前，不表示小臂与大臂共线。例如 `h2=20°` 时，大臂角 `A=110°`；小臂保持水平需要 `h3=0°`，相应算法相对肘角为 `q3=-110°`。腕部电机安装在小臂上，因此 `h4=0°` 时末端与小臂同向；要让末端水平，应令 `h4=-h3`（以当前方向和偏置为前提）。

算法的 `(q2,q3,q4)=(0,0,0)` 则表示三段连杆全都水平向前，不是硬件全零；按上述映射它对应 `(h2,h3,h4)=(-90°,0°,0°)`。四自由度只控制末端的 `x/y/z` 和一个俯仰角，`pitch_deg=0` 要求末端水平，不要求小臂水平。

## 2. 代码实际走过的角度链路

```text
MoveArmCartesian(x,y,z,pitch)
  -> kinematics.inverse_kinematics：求 q1,q2,q3,q4
  -> JointTransformer.algo_to_hardware：求 h1,h2,h3,h4
  -> PTP/LIN 生成硬件角轨迹 -> TrajectoryPoint (rad) -> 下位机

ArmStatus (实测 h1,h2,h3,h4)
  -> JointTransformer.hardware_to_algo：还原 q1,q2,q3,q4
  -> kinematics.forward_kinematics：LIN 起点的 xyz,pitch

MoveArmJoints / joints 预设
  -> 输入本来就是硬件角，直接插补；不经过 IK 和角度映射
```

源码位置：`kinematics.py` 的 `forward_kinematics` / `inverse_kinematics`，`joint_transformer.py` 的双向映射，`trajectory_planner.py` 的 PTP/LIN，`arm_planner_node.py` 的两个运动服务和状态回调。串口协议只规定四个 `float32` 关节角字段（rad），没有固件零位换算的实现证据。

## 3. 核查结果

| 级别 | 发现 | 依据与影响 |
| --- | --- | --- |
| 高 | 当前 Q3 偏置与描述的实机零位冲突 | `arm_presets.yaml` 当前为 `q3.offset_deg: 90.0`，而 `JointTransformer` 对 Q3 使用 `h3 = q2+q3+offset`。按“小臂水平时硬件角为 0°”，偏置应为 `0°`。当前配置把所有笛卡尔目标的小臂命令整体加了 `90°`。 |
| 高 | 错误偏置同时污染反馈 FK 和 LIN 起点 | 当前代码按 `B=h3-90°` 解释实测 Q3。若实机实际 `B=h3`，则估计的小臂与末端俯仰均偏差 `-90°`。LIN 会从错误的末端起点规划；第一个路点虽保留实测硬件角，后续路点仍可能产生大幅跳变。 |
| 中 | Q4 的几何公式正确，零位说明不准确 | `q4=pitch-(q2+q3)`、`h4=q4` 对“腕部电机相对小臂运动、零位与小臂同向”成立。配置和旧文档称“腕部水平朝前为 0°”容易被误读；小臂抬起时，`h4=0°` 的末端也随小臂抬起。实际腕部零位及方向仍需校准。 |
| 中 | `joints` 预设与笛卡尔请求可能表现不一致 | `zero/home/retract` 和 `move_joints` 直接发送硬件角，不受 Q3 偏置影响；笛卡尔 PTP/LIN 会使用错误偏置。只比较这些入口的动作会出现“关节命令正常、坐标命令不正常”。 |
| 说明 | 插补不是当前 90° 偏差的来源 | PTP 在硬件角之间使用相同的五次多项式比例插值；映射是仿射关系，端点正确时这种插补不会单独改变 Q3 的角度定义。LIN 对每个采样位姿重新做 IK；当前 YAML 的 `interpolation_step_ms=200` 对应目标采样间隔约 5 Hz，配置注释中的“20Hz”不准确。 |
| 说明 | `joint_states` 发布的是硬件角 | 节点把 `ArmStatus.joint_1..4` 原样发布为 `JointState.position`，没有转换为算法中的相对肘角。用常规“肘关节相对大臂”模型显示时，Q3 必须另行转换；仓库中未找到本机械臂的 URDF 可核对。 |
| 待核实 | 运动范围与几何参数 | Q3 上限当前改为 `180°`，但仓库没有实机机械限位依据；`a2/a3=0.26m` 等几何值也需测量轴心距。限位或长度不准会造成拒绝可达目标或末端位置误差。 |

### 一组可复算的数值

使用当前几何 `d1=0.14m`、`a2=a3=0.26m`、`a4=0.08m`，目标 `(x,y,z,pitch)=(0.20,0,0.25,0°)` 的肘上逆解约为：

```text
理论角：q2=114.27°，q3=-143.51°，q4=29.25°
大臂硬件角：h2=24.27°
小臂应有的绝对角：B=q2+q3=-29.25°
应下发：h3=-29.25°，h4=29.25° -> 末端俯仰 0°
当前配置下发：h3=60.75°，h4=29.25° -> 按所述实机结构，末端俯仰 90°
```

同样，`zero` 预设直接下发 `(h2,h3,h4)=(0,0,0)`。所述实机姿态应是大臂竖直、小臂和末端水平，模型算得末端约 `(x,z)=(0.34,0.40)m`；但当前反馈映射把这一状态解释成小臂和末端向下，FK 给出约 `(x,z)=(0,0.06)m`。这些数值仅由代码与所述传动关系推出，不是实机测量结果。

## 4. 核实和修正顺序

1. 在停机可控条件下核实下位机的原始 `ArmStatus.joint_3`：小臂物理水平向前时是否确为 `0 rad`，改变大臂角度且小臂保持水平时该读数是否仍接近 `0 rad`。同时核实 Q3 正角是否使小臂向上，以及电机角变化与小臂实际角变化是否为 1:1。
2. 核实 `h4=0` 时末端是否与小臂同向；固定小臂并单独改变 Q4，确认正角是否抬起末端。若不是，需重新标定 Q4 的 `offset_deg` / `direction`，不能用 Q3 偏置补偿。
3. 如果上述零位和正方向成立，将 `config/arm_presets.yaml` 的 `q3.offset_deg` 从 `90.0` 改为 `0.0`；保留现有 Q3 双向耦合公式。Q3 `limits_deg` 必须按实际电机角范围重新确认，不能通过加偏置或放宽限位掩盖零位错误。
4. 用已知的静止姿态核对 `ArmStatus` 与实测连杆角，再对比 FK 末端位置；之后才用低速、小范围动作检查笛卡尔 PTP 和 LIN。`move_joints` 的第三项和 `joints` 预设的第三项始终是小臂硬件绝对角。

当前未修改配置或控制代码。文档所用实机假设需要下位机零位和反馈数据验证；仓库内的协议定义与生成回调桩无法证明固件内部是否另加了角度偏置。
