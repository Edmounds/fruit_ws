## 一、通信架构与物理链路

上位机与下位机通过单个 USB 虚拟串口实现全双工二进制通信：
- **设备节点**：默认 `/dev/stm32`（波特率 `115200`）；
- **通信框架**：`auto_serial_bridge`；
- **职责边界**：
  - 上位机负责运动学逆解、轨迹生成与分步下发；
  - 下位机负责环形队列缓冲、定时器中断线性步进插补与电机闭环 PID；
  - 协议统一由 `src/auto_serial_bridge/config/protocol.yaml` 自动生成，双方无须手写底层封包代码。

## 二、数据帧底层结构与校验安全

下位机与 ROS 之间的每一帧二进制报文均遵循严格的帧封装格式：

```text
┌───────────┬───────────┬────────────┬───────────┬─────────────┬───────────┐
│ 帧头 1     │ 帧头 2     │ 消息 ID    │ 数据长度 L │ 有效负载 Payload │ 校验码    │
│ 0x5A (1B) │ 0xA5 (1B) │ MsgID (1B) │ Len (1B)  │ L 字节       │ CRC8 (1B) │
└───────────┴───────────┴────────────┴───────────┴─────────────┴───────────┘
```

1. **帧头字节 (`0x5A 0xA5`)**：用于在连续字节流中准确定位一帧数据的起始位置；
2. **消息 ID (`MsgID`)**：`0x00 ~ 0xFC` 为业务消息，`0xFD ~ 0xFF` 为通信框架保留消息（Ack, Heartbeat, Handshake）；
3. **CRC8 校验码**：覆盖从消息 ID 到 Payload 末尾的全部字节，任何单比特电平抖动导致的数据损坏均会被下位机硬件直接丢弃，杜绝电机误动。

## 三、机械臂 4 条核心业务报文规范

协议中与机械臂运动直接相关的报文共有 4 条（3 条下行控制指令 + 1 条上行遥测状态）：

```text
         上位机 (fruit_arm_planner)                        下位机 (STM32)
                     │                                            │
                     │── 1. TrajectoryHeader (0x10) [TX, ACK] ───►│
                     │── 2. TrajectoryPoint  (0x11) [TX, ACK] ───►│
                     │── 3. ArmControlMode   (0x12) [TX, ACK] ───►│
                     │                                            │
                     │◄── 4. ArmStatus       (0x20) [RX, 20Hz] ───│
```

---

### 1. `TrajectoryHeader`（ID: `0x10`，轨迹任务声明包）
- **传输方向**：TX（上位机 $\to$ 下位机），**启用 Reliable ACK**
- **ROS 话题**：`/fruit_hardware_bridge/arm/trajectory_header`
- **消息类型**：`fruit_hardware_interfaces/msg/TrajectoryHeader`
- **功能描述**：在下发一组路点前，先向单片机宣告即将下发的任务 ID 与路点总数。

| 字段名称 | 协议类型 | C 语言类型 | 字节大小 | 含义说明 |
| :--- | :---: | :---: | :---: | :--- |
| `trajectory_id` | `u32` | `uint32_t` | 4 字节 | 任务唯一流水号（如 1001, 1002） |
| `point_num` | `u16` | `uint16_t` | 2 字节 | 该轨迹包含的路点总数量 $N$ ($1 \le N \le 128$) |

> **单片机接收动作**：单片机校验无误后，清空历史残余轨迹缓冲区，重置写入指针，开辟能容纳 $N$ 个路点的临时缓冲区。

---

### 2. `TrajectoryPoint`（ID: `0x11`，航路点数据包）
- **传输方向**：TX（上位机 $\to$ 下位机），**启用 Reliable ACK**
- **ROS 话题**：`/fruit_hardware_bridge/arm/trajectory_point`
- **消息类型**：`fruit_hardware_interfaces/msg/TrajectoryPoint`
- **功能描述**：下发单个航路点的关节目标位置、执行时刻与夹爪动作。

| 字段名称 | 协议类型 | C 语言类型 | 字节大小 | 含义说明 |
| :--- | :---: | :---: | :---: | :--- |
| `trajectory_id` | `u32` | `uint32_t` | 4 字节 | 所属任务流水号（必须与 Header 一致） |
| `point_id` | `u16` | `uint16_t` | 2 字节 | 航路点序号（从 `0` 到 `N-1` 连续单调递增） |
| `time_from_start` | `u32` | `uint32_t` | 4 字节 | 距轨迹起点的毫秒数（单位: `ms`，单调递增） |
| `joint_1` | `f32` | `float` | 4 字节 | Q1 基座物理目标角度（弧度制 rad） |
| `joint_2` | `f32` | `float` | 4 字节 | Q2 大臂物理目标角度（弧度制 rad） |
| `joint_3` | `f32` | `float` | 4 字节 | Q3 小臂物理目标角度（弧度制 rad） |
| `joint_4` | `f32` | `float` | 4 字节 | Q4 腕部物理目标角度（弧度制 rad） |
| `gripper_action` | `u8` | `uint8_t` | 1 字节 | 夹爪控制动作：`0`=保持, `1`=张开, `2`=闭合 |

> **单片机接收动作**：单片机将路点数据按 `point_id` 顺序存入执行队列。

---

### 3. `ArmControlMode`（ID: `0x12`，控制模式与执行指令）
- **传输方向**：TX（上位机 $\to$ 下位机），**启用 Reliable ACK**
- **ROS 话题**：`/fruit_hardware_bridge/arm/control_mode`
- **消息类型**：`fruit_hardware_interfaces/msg/ArmControlMode`
- **功能描述**：触发轨迹启动、平滑制动停机或硬件最高优先级急停。

| 字段名称 | 协议类型 | C 语言类型 | 字节大小 | 模式取值规范 |
| :--- | :---: | :---: | :---: | :--- |
| `control_mode` | `u8` | `uint8_t` | 1 字节 | **`0`**: 启动轨迹执行 (TRAJECTORY)<br>**`1`**: 平滑减速停机并复位 (STOP)<br>**`2`**: 硬件切断急停锁死 (ESTOP) |

- **模式 0 (TRAJECTORY)**：路点传输完成后点火触发，下位机启动定时器中断驱动电机运转；
- **模式 1 (STOP)**：受控平滑减速制动，清除未走完的残留路点，复位为 `IDLE (0)` 状态；
- **模式 2 (ESTOP)**：立即切断电机驱动脉冲，电机抱死，进入 `EMERGENCY (4)` 锁定状态（必须发送模式 1 才能解除解锁）。

> ⚠️ **核心工程认知：为什么已有物理实体急停键，上位机仍必须发送 `ArmControlMode`？**
> 1. **`mode=0` 是下位机单片机的“点火信号”**：下位机在收到 `Header` 和多个 `Point` 时，只负责将其存入 RAM 环形队列，此时电机绝对不会转动（防止数据包还在空中传输时电机因缺帧失速）。**只有收到 `ArmControlMode(0)` 时，单片机才确认“所有点已集齐”，立刻启动高精度定时器中断驱动电机**！如果不发 0，下位机将永久处于等待缓存状态；
> 2. **`mode=1/2` 是上位机软件看门狗安全兜底**：下位机实体急停键是现场人员肉眼发现危险时的物理保底；而上位机的 `mode=1/2` 是用于自动化任务中的**软件看门狗**——例如采摘动作预期 3 秒，若 5 秒后下位机因卡死仍未上报完成，上位机代码可自动下发 `STOP` 停机，杜绝程序无人看守时电机堵转烧毁。
> 3. **对上层 mission 完全隐蔽**：上位机解算节点在后台自动打出 `mode=0` 完成点火，对上层 mission 业务状态机完全透明，无需上层人工发此指令。

---

### 4. `ArmStatus`（ID: `0x20`，单片机 20Hz 综合状态上报）
- **传输方向**：RX（下位机 $\to$ 上位机），周期广播，**不设 ACK 重传**
- **ROS 话题**：`/fruit_hardware_bridge/arm/status`
- **消息类型**：`fruit_hardware_interfaces/msg/ArmStatus`
- **功能描述**：下位机以每 50 毫秒（20Hz）周期主动回传实测关节物理位置、角速度、执行进度及错误报警码。

| 字段名称 | 协议类型 | C 语言类型 | 字节大小 | 说明 |
| :--- | :---: | :---: | :---: | :--- |
| `trajectory_id` | `u32` | `uint32_t` | 4 字节 | 当前正在执行或刚完成的任务编号 |
| `task_status` | `u8` | `uint8_t` | 1 字节 | `0`=空闲 (IDLE), `1`=运行中 (RUNNING), `2`=完成 (COMPLETED), `3`=失败 (FAILED), `4`=急停 (EMERGENCY) |
| `progress` | `f32` | `float` | 4 字节 | 执行进度百分比 (`0.0 ~ 100.0%`) |
| `joint_1` ~ `joint_4` | `f32` | `float` | 16 字节 | 4 个关节当前编码器实测物理弧度 (rad) |
| `joint_1_vel` ~ `4_vel` | `f32` | `float` | 16 字节 | 4 个关节当前瞬时角速度 (rad/s) |
| `gripper_state` | `u8` | `uint8_t` | 1 字节 | 夹爪当前物理状态：`0`=保持/未知, `1`=张开, `2`=闭合 |
| `error_code` | `u16` | `uint16_t` | 2 字节 | `0`=正常, `1001`=超时报警, `1002`=超限报警, `1003`=急停触发 |

## 四、可靠消息 (Reliable ACK) 重传机制

轨迹相关的三条控制报文（Header, Point, ControlMode）均配置了 `reliable: true`：
1. **握手确认**：上位机发送后，启动 1000ms 定时器并等待单片机回复内置确认帧 `Ack(0xFD)`；
2. **超时重发**：若由于串口噪声导致单包数据丢失，通信层自动以 1000ms 间隔自动重传；
3. **报警兜底**：连续重传 3 次未收到确认时，控制层打印告警日志，但仍持续尝试，杜绝路点静默丢失造成的关节剧烈跳动。

## 五、轨迹下发三步法时序契约与闭环流转

上位机节点 `arm_planner_node` 在下发任何运动时，均严格遵循以下执行规程：

```text
上位机 fruit_arm_planner                               下位机 STM32 单片机
           │                                                    │
           │ 1. TrajectoryHeader(id=1001, point_num=N)          │
           ├───────────────────────────────────────────────────►│ 申请缓冲区，计数归零
           │                                                    │
           │ 2. 循环发送 point_0 到 point_{N-1}                 │
           ├───────────────────────────────────────────────────►│ 逐点写入环形队列
           │                                                    │
           │ 3. ArmControlMode(control_mode=0)                  │
           ├───────────────────────────────────────────────────►│ 启动插值定时器，进入 RUNNING
           │                                                    │
           │ 4. 20Hz 遥测状态 ArmStatus(task_status=1, progress)│
           │◄───────────────────────────────────────────────────┤ 每 50ms 周期广播进度
           │                                                    │
           │ 5. 执行完成 ArmStatus(task_status=2, progress=100) │
           │◄───────────────────────────────────────────────────┤ 恢复 IDLE 空闲状态
```
