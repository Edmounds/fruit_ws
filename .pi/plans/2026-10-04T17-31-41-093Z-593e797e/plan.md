## 决策

1. **先规则与交接，不做技术强制。** 这只能指导遵守规则的 Agent，不能阻止工具绕过，也不能消除并发写入的竞争窗口。
2. **阶段提交必须执行。** 完成可验证的小阶段即提交，只暂存能明确归属本会话的文件或 hunks，提交前检查 staged diff。禁止 `git add .`、`git add -A`、`git commit -a` 等夹带他人改动的操作。遵守现有 hooks，不用 `--no-verify`。检查失败、归属不明、共享索引不可安全操作时先报告阻塞，不冒充完成。
3. **最终一个任务提交。** 只整理本任务未共享分支历史，先保留可定位的原提交恢复点；若分支混有其他任务提交、已共享或无法确认边界，则停止整理并询问。禁止为压缩任务提交而重写 main。直接在 main 开发仍允许，自己的阶段提交照常做，但已进入 main 的提交不自动压缩；需要压缩的任务使用独立 worktree。
4. **保护 main 最新意图，不机械选边。** 对比共同祖先、最新 main、本任务改动，既检查文本冲突，也检查调用关系、接口、配置和行为冲突。能保留两边意图则在自己的 worktree 适配；含糊或必须改变 main 意图时先询问用户。禁止复制旧整文件覆盖、冲突全量选择 ours/theirs、强制恢复/清理 main、强推 main。
5. **main 脏或有活跃写入时不集成。** 包括 staged、unstaged 和未跟踪成果。不得自动 stash main、提交他人的工作或拿走其正在编辑的内容。用户已选择不暂停这些会话，因此当场集成不是必须完成项；不自动后台重试。
6. **开发会话可自行集成，但必须串行。** main 干净且确认无人写入、同一时间只有一个集成者时，在隔离 worktree 适配最新 main 并验证；最终 main 只接受已验证的快进结果。再次检查 main HEAD、工作区和会话协调状态，任何变化都使之前的分析失效，返回适配/验证。不能以“status 干净”等同于“没有其他写入者”。
7. **持久交接依托提交，不新增队列工具。** 待集成时最终提交正文记录任务内容、验证证据与限制、当时 main 基线、待集成状态和下一步；最终回复给出仓库路径、worktree、分支、SHA。保留分支与 worktree，禁止用“已完成合并”描述它。后续承担集成的会话先扫描未合并任务分支并阅读提交正文；真正集成成功后才清理任务分支/worktree。
8. **例外不能隐瞒。** 只规划、没有代码改动、非 Git 规则文件、检查失败、提交身份/hooks 不可用等情况如实报告。不为了制造提交而 init 新仓库、修改身份、绕过 hooks 或夹带其他工作。独立仓库、submodule 的改动需分别核对其提交归属。
9. **只覆盖已确认的入口。** 本次落地 Pi、Codex 用户级规则和 fruit_ws 局部对齐。新客户端、额外入口或需要改扩展才能加载规则时，先询问，不能悄悄扩大范围。

## 风险

- 纯文字规则不是强制保护；不遵守规则的 Agent 仍可能损坏文件，真正强制拦截属于后续独立任务。
- main 工作区干净不代表没人正在写；Git 的文件锁不等于多会话集成锁。用户已接受无法确认安全时暂缓，不能承诺无协调的并发集成安全。
- 暂缓交接依赖后续会话扫描和接手，不保证无人介入时自动合并；丢失整个机器/仓库仍可能丢失本地分支，默认提交并不等于远程备份。
- 压缩会改变分支提交 SHA，误判共享状态会影响其他会话；必须限定归属、保留恢复点、不能重写 main。
- 用户所述历史覆盖的实际命令尚未取证；只解释机制并防止危险行为，不猜测哪个 Agent 或命令造成事故。
- 全局规则文件可能不在 Git 内；需本地恢复副本及明确报告，不伪造已提交状态。
- 当前 `AGENTS.md` 已有用户改动，且仓库大量并发/未提交工作；精确暂存仍需要避免共享索引竞争，归属不清立即停止。
- AnySearch 配置残留异机路径，调研需运行时回退核实；服务不可用时不能无审批跳过明确的联网需求。
- 本次仅确认 Pi/Codex 两个用户级入口；其他客户端和已运行旧会话的规则生效情况不在已验证范围。
